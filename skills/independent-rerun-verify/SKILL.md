# independent-rerun-verify

這是一份**流程指引**，把「獨立重跑」的驗收方式固定成可重複套用的步驟：
**從現行原始碼自己建置、自己重跑，不採信實作方的產物或結論**，並用**對照組**
證明斷言真的抓得到它宣稱要抓的 bug。

- 它是驗證手法，不是測試框架；不下載或安裝工具，也不改專案設定。
- 實作方的報告只當**對照**：它的數字可以拿來比對，但**不是你自己的證據**。
- 沒有跑到的項目寫「未測」，不以推論代替。

## 什麼時候用

- 修復輪的驗收，或高風險改動：競態條件、取消行為、錯誤處理、契約變更、資料格式變更。
- 實作方提供了自建 bundle、報告或測試輸出，需要避免「沿用同一份產物而落入相同盲區」。
- 需要排除**空過測試**（test that cannot fail），或需要證明斷言真的守得住回歸。
- 宣稱「修好了」但沒有可重現證據時。

## 步驟

1. **自建**：以現行原始碼重新建置，或依目標 commit 建置；**不沿用**實作方給的產物。
   建置指令、版本與環境一併記下。
2. **修前重現**：從目標 commit 匯出該版檔案建置（例如用版本控制取出該版內容），
   實際重現被宣告的問題，記錄修前的行為作為對照。
3. **對照組（證明斷言抓得到）**：暫時反轉實作、移除關鍵檢查或刻意注入等效缺陷，
   確認測試**真的失敗**；跑完**立即還原**。若怎麼改都不會失敗，該斷言視為可疑，
   要查是斷言太弱、測錯目標，還是根本沒被執行。
4. **還原驗證**：還原後與原檔逐位元比對，或比對雜湊值一致；不一致就重做還原。
5. **重跑**：以自建產物重跑完整驗證，記下通過與失敗的項目。
6. **記錄**：把修前失敗、修後通過、對照組失敗、還原一致四類證據一起寫進驗收紀錄。

## 四個必備證據

| 證據 | 說明 | 缺了會怎樣 |
| --- | --- | --- |
| 自建產物 | 以現行原始碼或目標 commit 自行建置 | 沿用作業產物，會與實作端同錯 |
| 修前重現 | 該問題在修前確實發生，並記下當下行為 | 「本來就沒問題」與「修好了」分不出來 |
| 對照組失敗 | 反轉或注入缺陷後斷言失敗，之後完整還原 | 無法排除空過測試 |
| 還原一致 | 還原後與原檔位元或雜湊相同 | 對照組可能留下污染，後續結果不可信 |

## 對照組的安全規則

- 只在**工作區的暫存副本或可完全還原的位置**做反轉與注入。
- 反轉前先留下原檔的雜湊，還原後再比對；**對照組結束就還原**，不要留到下一輪。
- 對照組屬於驗證手段，**不得**進版控、不得留在產物裡、不得被當成正式程式碼。
- 對照組若牽涉機密或個資，改用合成資料，不要動真實資料。

## 輸入與輸出

- 輸入：待驗的 commit 或變更範圍、宣稱的行為、專案既有的建置與測試指令、
  實作方報告（僅供對照）。
- 輸出：自建產物與其建置方式、修前失敗與修後通過的結果、對照組失敗的結果、
  還原一致的證據，以及沒有驗到的項目清單。

## 明確不做的事

- 不刪除、不跳過（`skip`）、不弱化既有測試或斷言來讓結果變綠。
- 不在實作裡針對測試輸入寫死結果，也不用空例外處理吞掉錯誤。
- 不以實作方的截圖、報告或結論當成自己的驗證證據。
- 不改寫歷史、不強制推送、不動不屬於本任務的檔案。
- 不宣稱「全部驗過」——只宣稱實際跑過、且證據齊備的項目。
