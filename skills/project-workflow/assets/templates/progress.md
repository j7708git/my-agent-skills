# 進度（progress）

> 使用方式：把整份檔案複製到 private notes repo 的專案目錄，命名為 `progress.md`。
> 所有 `<...>` 都要換成實際值；commit 欄位只能填**真實已存在**的 commit，不要填預期值。
> **不必每一輪把整份歷史無限追加**：保留頂部「最新摘要」代表現況，歷史交給 Git 與
> 簡短里程碑記錄保存；不要刪掉唯一的工作紀錄。

## 骨架

```markdown
# 進度：<專案名稱>

> **讀者**：<接手這個專案的人；寫明對專案的熟悉程度>
> **一句話**：<這個專案現在進行到哪裡、下一步是什麼>
> **現在要做**：<讀完後要接手或回報的動作>
> **依據**：<任務卡、commit、日誌或決策紀錄>

## 最新摘要（<YYYY-MM-DD HH:MM>）

- 最新摘要：<一到三句說明現況>
- 當前目標：<這一輪要達成什麼>
- 目前階段：<規劃／原型／實作／驗收／維護>
- 程式碼目錄（相對 workspace）：<code-root 相對 workspace 的路徑，或 N/A>
- code repo 分支：<branch 名稱>
- code repo commit：<真實已存在的 commit SHA（短版即可）>
- commit 是否已 push：<是／否（僅本機）>
- remote 可達性：<遠端存在／尚無 remote／無法確認>
- code repo 同步狀態：<乾淨／有未 commit 變更／領先遠端 N 筆／落後 N 筆／diverged>
- notes repo 同步狀態：<同上；與 code repo 分開寫>
- 已確認：<已確定的事實>
- 假設：<目前依賴的假設>
- 未知：<仍不確定、且會影響方向的事>
- 已完成：<已完成的事>
- 待完成：<還沒做的事>
- 驗收（已測）：<已實際驗證的項目與結果>
- 驗收（未測）：<尚未驗證的項目與原因>
- 待決定事項：<需要使用者或 PM 拍板的問題>
- 下一步可行動任務：<具體、可執行>
- 阻塞與風險：<目前卡住的地方與風險>

## 里程碑（可選、簡短）

- <YYYY-MM-DD>：<里程碑與結果>
```

## 欄位填寫規則

| 欄位 | 填寫規則 |
| --- | --- |
| 最新摘要 | 一到三句，描述「現在在哪裡」；更新時改這裡，不必重貼整份歷史 |
| 當前目標 | 這一輪的目標，用動詞開頭 |
| 目前階段 | 只能選規劃／原型／實作／驗收／維護 |
| 程式碼目錄 | code-root 相對 workspace 的路徑；研究任務沒有程式碼就寫 N/A |
| code repo 分支 | 寫實際分支名，不要寫「主要分支」 |
| code repo commit | 真實已存在的 commit SHA；沒有就寫 N/A |
| commit 是否已 push | 明確寫是或否；「是」要有遠端依據，不確定就寫不確定 |
| remote 可達性 | 遠端存在、尚無 remote，或無法確認三者之一 |
| code repo 同步狀態 | 與實際 `git status` 一致；有未 commit 就明寫 |
| notes repo 同步狀態 | 同上；兩個 repo 分開寫，不要合併 |
| 已確認／假設／未知 | 分開寫；假設要能被推翻，未知要寫影響 |
| 已完成／待完成 | 對應當前目標；待完成用動詞開頭 |
| 驗收（已測／未測） | 已測附實際結果；未測明說原因，不要美化 |
| 待決定事項 | 寫成「需要誰決定什麼」，不要只寫問題 |
| 下一步可行動任務 | 具體到可以照做 |
| 阻塞與風險 | 有就寫，沒有寫「無」 |
| 里程碑 | 只留簡短紀錄；完整歷史由 Git 保存，不要刪掉唯一紀錄 |
| 開頭四欄 | 標題後先用 blockquote 放讀者（含熟悉度）、一句話、現在要做、依據；四欄都要有實質內容。 |

## 注意

- 不要寫「已同步」卻沒有實際 push；建立檔案不等於已同步。
- 不要把 private notes 的具體連結貼進公開文件。
- 未 push 的 commit 只在本機可見，跨機時必須明說。
- 保留舊紀錄；「最新摘要」是現況，不是唯一歷史。
