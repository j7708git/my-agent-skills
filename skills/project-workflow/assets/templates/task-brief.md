# 任務簡報（task-brief）

> 使用方式：把整份檔案複製一份，針對單一任務填寫，交給 worker。
> 子 agent 沒有你的上下文，所以簡報必須**自足**；所有 `<...>` 都要換成實際內容。
> 「權限說明」只是說明，不是權限設定；不要把簡報當成授權。

## 骨架

```markdown
# 任務簡報：<任務名稱>

## 1. 任務類型與目標

- 類型：<實作／研究／文件／驗收>
- 目標：<要做什麼、怎麼算完成>

## 2. 兩個 repo 根

- code-root：<路徑；研究任務寫 N/A>
- notes-root：<路徑>
- 路徑基準：<以哪個目錄為基準解析相對路徑>

## 3. 必讀背景

- <相對路徑>：<為什麼要讀>

## 4. 已知／假設／未知

- 已知：<可查證的事實>
- 假設：<可逆的預設>
- 未知：<不確定之處>

## 5. 範圍與 non-goals

- 範圍：<本任務要做的>
- non-goals：<本任務明確不做的>

## 6. 行為、輸入輸出與錯誤處理

<輸入、輸出、錯誤處理；研究任務改寫「研究問題與證據標準」>

## 7. 驗收方法與成果

- 驗收方法：<實際指令或觀察方式>
- 預期成果：<產出檔案／報告>

## 8. 限制與停止條件

- 限制：<不可使用的工具、不可修改的檔案>
- 停止條件：<卡住時何時停下回報>

## 9. 允許寫入的檔案或目錄

- <明確清單>

## 10. worker 禁止事項

- 不得動 private repo 的 Git index（不 git add、不 commit）。
- 不得超出本簡報範圍；有需要請回報。
```

## 欄位填寫規則

| 欄位 | 填寫規則 |
| --- | --- |
| 任務類型與目標 | 類型只能選實作／研究／文件／驗收；目標要可判定 |
| code-root／notes-root | 寫實際路徑；研究任務的 code-root 寫 N/A |
| 路徑基準 | 明說相對路徑以哪個目錄為基準，避免 worker 猜 |
| 必讀背景 | 用相對路徑，並說明為什麼要讀 |
| 已知／假設／未知 | 把不確定性寫進簡報，不要留給 worker 猜 |
| 範圍／non-goals | 兩者都要寫，避免 worker 自行擴大 |
| 行為與輸入輸出 | 實作任務寫清楚；研究任務改成研究問題與證據標準 |
| 驗收方法 | 要能實際執行或觀察，不要只寫「確認正確」 |
| 限制與停止條件 | 限制與停止條件都要寫，卡住時才知道何時回報 |
| 允許寫入 | 明確列出檔案或目錄，不用「專案目錄」這種模糊範圍 |
| worker 禁止事項 | 必含不得動 private repo index、不得擴大範圍 |
| 權限說明 | 明說這只是說明；實際授權由使用者決定 |
