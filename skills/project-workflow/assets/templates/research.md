# 研究（research）

> 使用方式：把整份檔案複製到 private notes repo 的專案目錄，命名為 `research.md`。
> 先完成「小樣本階段」，確認報告 shape 後再擴大。所有 `<...>` 都要換成實際內容。
> 事實、推論、未確認必須分開寫。

## 骨架

```markdown
# 研究：<主題>

- 專案 ID：<project-id>

## 研究問題

<這次要回答的具體問題>

## 已知

- <已確認的事實>

## 假設

- <待驗證的假設>

## 未知

- <尚未確認的問題>

## 方法

<資料來源與比較方式；不下定論的界線>

## 小樣本階段

<先用小樣本確認 shape 的做法與結果>

## 報告 shape

- <欄位一>：<要回答什麼>
- <欄位二>：<要回答什麼>

## 來源清單

- <來源>：<版本>；查閱日期 <YYYY-MM-DD>

## 事實

- <可追溯到來源的事實>

## 推論

- <由事實推出的判斷，註明依據>

## 未確認

- <查不到、或無法確認的事項（未找到不等於不存在）>

## 收斂結論

<在目前證據下可以下的結論與其界線>

## 下一步

- <後續要查或要驗證的事>
```

## 欄位填寫規則

| 欄位 | 填寫規則 |
| --- | --- |
| 研究問題 | 一次聚焦一個問題，避免包山包海 |
| 已知／假設／未知 | 三欄分開；假設要能被證偽 |
| 方法 | 寫出資料來源與判斷界線 |
| 小樣本階段 | 先小後大；記錄小樣本結果再決定是否擴大 |
| 報告 shape | 先定欄位與要回答的問題，避免白做 |
| 來源清單 | 每筆都要有版本與查閱日期 |
| 事實／推論／未確認 | 三者不得混寫；推論要註明依據 |
| 未確認 | 查不到就寫未確認，不要推論成不存在 |
| 收斂結論 | 只寫證據支撐得住的結論，並寫界線 |
| 下一步 | 用動詞開頭，具體可執行 |
