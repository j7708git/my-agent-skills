# web-ui-e2e-smoke

這是一份**流程指引**，把 Web UI 的端到端冒煙驗收固定成可重複套用的步驟：
以**真實建置的產物**、**可達的後端**與**真實瀏覽器驅動**逐步操作，並留下截圖證據。

- 它不是測試框架，不下載或安裝任何工具，也不修改專案設定。
- 「有截圖」不等於「已驗證」：每一步都要有明確斷言與實際觀察。
- 缺少瀏覽器或驅動時如實回報「未測」；**不要**用單元測試結果或程式碼閱讀冒充 UI 驗證。
- 它不取代隱私掃描，也不提供任何安全保證。

## 什麼時候用

- 驗收條件涉及只有真實瀏覽器能確認的行為：進度會動、可取消、下載按鈕可用、
  雙擊不誤報、失敗可重試、錯誤訊息正確。
- 任務改動 web 前端或本機服務的 UI，要求「真的開起來操作過」才算驗收。
- 待測服務只綁 loopback（`127.0.0.1`），內建瀏覽器面板連不到，必須繞道驅動。
- 需要對外留下「逐步操作＋截圖」的證據，而不是只有一句「已測試」。

## 前置條件

1. **真實建置**：以現行程式碼重新建置前端產物，**不得沿用前一輪留下來的 bundle**。
   建置指令與工具版本一併記下來。
2. **可達的後端**：
   - 能用真的 server 就用真的；只驗 UI 流程時可用 mock，但**必須明示是 mock**。
   - 若服務只綁 loopback 而驅動端連不到，改用綁區網位址的等效設定（真 server 或 mock），
     並在回報中寫明這個替代與理由。
   - 需要 token 時用測試用 token，隨機埠，不要寫死實際憑證。
3. **驅動方式**（擇一，並在回報中註明）：
   - 內建瀏覽器面板（服務可達時優先）。
   - 系統瀏覽器搭配 CDP 驅動。
   - 環境既有的 playwright。
4. **情境清單**：從驗收條件逐條列出要操作與斷言的步驟，含**反例**。

## 步驟

1. 依前置條件建置出乾淨的 dist，記下建置指令與產物位置。
2. 啟動後端（真 server 或 mock），選定可達位址、埠與測試 token，記下啟動指令。
3. 連上驅動（面板／CDP／playwright），先確認頁面真的載入到本次建置的版本。
4. **逐情境斷言**：依清單逐步操作，每步記 pass 或 fail；失敗要留重現步驟。
5. **反例也要跑**：雙擊、重複提交、409 衝突、中斷後重試、取消後再啟動等。
   只跑正向路徑不算完成。
6. **截圖留證**：每個斷言點截圖，統一放在本次任務專屬的截圖目錄
   （放在忽略版控的暫存位置，不要散落在專案目錄裡）。
7. **清收**：關掉自己啟動的瀏覽器、mock server、無頭顯示器等行程，並確認沒有殘留。
8. **回報**：步驟表＋截圖位置＋環境註記；失敗項附重現步驟。

## 每一項斷言要交代的事

| 欄位 | 內容 |
| --- | --- |
| 情境 | 對應哪一條驗收條件 |
| 操作 | 實際做了什麼（點擊、輸入、等待多久） |
| 預期 | 應該觀察到什麼 |
| 實際 | 真的觀察到什麼 |
| 判定 | pass／fail |
| 證據 | 截圖位置（可對照的當下畫面） |
| 環境 | 建置版本、驅動方式、後端來源（真／mock）與位址 |

- 時間相關的行為（進度、動畫、取消）要寫**觀察方式與時間窗**，
  不能只寫「看起來有動」。
- 沒有實際跑到的情境寫「未測」，不要留白或推定通過。

## 失敗處理

- 斷言失敗時先分辨是**產品缺陷**還是**環境問題**（埠衝突、殘留行程、舊 bundle）。
- 環境問題修正後重跑，並在回報中說明重跑原因；不要用「重跑就過了」帶過。
- 無法在目前環境完成的情境，明確列出並說明缺什麼，交由決策者決定是否補驗。

## 輸入與輸出

- 輸入：前端建置指令或產物、後端啟動方式與測試 token、驗收情境清單。
- 輸出：逐步 pass／fail 表、截圖、環境註記；失敗項含重現步驟。

## 明確不做的事

- 不沿用前一輪的建置產物當證據；不拿實作方的截圖當自己的驗證結果。
- 不為了讓某步驟變綠而放寬斷言、跳過反例或改寫驗收條件。
- 不下載或安裝新的瀏覽器、驅動或套件；環境缺少時回報，由使用者決定。
- 不清理不屬於本次任務的行程或檔案；只清自己啟動的。
- 不宣稱「UI 沒問題」——只宣稱實際操作過的範圍與結果。
