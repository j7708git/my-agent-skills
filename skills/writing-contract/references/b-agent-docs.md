# B 類規則：給 agent 看的指令檔

> B 類文件的讀者是 agent，不是第一次接觸專案的人。它要能在**動手當下**回答
> 「現在做什麼、先做哪個、衝突時聽誰的、什麼時候停」。若本檔與程式碼或測試不符，
> 以程式碼與測試為準。

## B1 優先序句（唯一的形式規則）

第一段逐字如下（`{line}` 由回報者換成實際行號）：

```text
> 本檔若與程式碼、測試或實際指令不符，以程式碼為準；安全邊界、授權與不可逆操作則以本檔為準。發現不符時：照程式碼做，並在回報中指出「本檔第 {line} 行已過期」。
```

機械檢查只比對句首前綴：

```text
> 本檔若與程式碼、測試或實際指令不符，以程式碼為準
```

### 為什麼

過期指令檔會勝過程式碼：有研究觀察到 agent 在 90.1% 的選擇裡跟著過期指令檔走，
即使它已經指出衝突。加一句顯式優先序，可以把「跟著程式碼」的比例從 4.2% 拉到
91.4%。這是預印本、合成專案與單一語言的結果，不能當成所有環境的保證。

### 何時可刪

本檔只描述不涉及程式碼的內容，例如純寫作偏好、語氣或格式慣例。只要文件會描述
程式行為、指令、參數或安全邊界，就不能刪。

### 插入位置

1. 有 frontmatter 的檔案：插在結尾 `---` 之後、**第一個非空行之前**。
2. 沒有 frontmatter 的檔案：插在檔案第一行之前。
3. 若原本的第一個非空行是 `>` 引言區塊，B1 要插在該區塊**之前**，成為第一段。
4. 不要改動任何以 `## N. ` 開頭的標題行或它們的順序；那些標題受契約測試保護。

### 同步對象

- 派工簡報模板與 PM 的內嵌骨架：`task-brief.md` 與 `pm.md` 的**內嵌骨架前導句**
  必須逐字相同；`pm.md` 的骨架縮排要保留兩個空格。
- B 類檔案的清單以集合 repo 的檢查器為準；本 skill 目錄內的規則檔本身**豁免** B1，
  因為它們定義規則，不描述程式行為。

## B2 只寫三類內容（僅人工自檢，無機械檢查）

B 類文件只放三類內容，其餘刪掉：

1. **可執行指令**：要在哪裡做、用什麼指令、怎麼確認成功。
2. **專案特有約定**：外部查不到的路徑、命名、角色、授權邊界。
3. **禁止事項與停止條件**：什麼不能做、卡住時何時回報。

通用寫作規則、動機長文、產品概觀與其他 skill 已有的流程不要重抄。每一條指令
都要附「怎麼驗」；沒有驗法的要求，通常只是願望。

## B3 不寫概觀（僅人工自檢，無機械檢查）

不要把關鍵事實只放在遠方的大文件。agent 會自發讀文件，但很少因為失敗才回頭查；
文件通常落後於程式碼。把「現在要知道的事」放在指令檔、任務卡或測試旁。

安全、授權與不可逆操作的例外必須保留，而且要與 B1 的「安全邊界以本檔為準」
一致：該寫的風險不能為了精簡而刪。

## 規則與理由

| 規則 | 形式 | 為什麼 | 何時可刪 |
| --- | --- | --- | --- |
| B1 優先序句 | 第一段逐字 | 過期指令檔會勝過程式碼；顯式優先序把跟隨程式碼的比例拉高 | 本檔只描述不涉及程式碼的內容 |
| B2 只寫三類 | 僅人工自檢 | 通用規則已被現成 skill 與原規範覆蓋，抄進來只會讓檔案變長 | 不降級 |
| B3 不寫概觀 | 僅人工自檢 | agent 讀的文件多數是 agent-facing 產物；關鍵事實要放在動手處 | 不降級 |

## 與其他規則的衝突

| 對 | 裁決 |
| --- | --- |
| B1 × B3 安全例外 | B3 的例外條款與 B1 的「安全邊界以本檔為準」是同一件事的兩面，必須一致 |
| B2 × B1 | B1 的回報要求（指出過期行）就是 B2「怎麼驗」的一種 |
| B1 × 精簡 | 優先序句是固定句，不因精簡而縮寫；縮寫會讓機械檢查與同步失效 |
